05Test CAN với Arduino UNO

Node test Arduino UNO gửi CMD 0x100 và in RESPONSE / STATUS / HEALTH. Nạp firmware: Build & triển khai 08. Đấu nối: Phần cứng.

05.1 · Mở cổng COM

05.1.1 · Cách 1 · PuTTY (khuyên dùng)

  1. Tải putty.exe (bản 64-bit, chạy luôn không cần cài).
  2. Mở PuTTY → Session: Connection type = Serial, Serial line = COM5, Speed = 115200.
  3. Tuỳ chọn: Terminal → Local echo = Force on để thấy chữ mình đang gõ. Firmware cũng in lại lệnh với dấu > sau khi nhấn Enter.
  4. Bấm Open. Gõ lệnh, nhấn Enter (PuTTY gửi CR, firmware nhận được). Backspace dùng được.

Mở nhanh từ dòng lệnh: putty.exe -serial COM5 -sercfg 115200,8,n,1,N

05.1.2 · Cách 2 · arduino-cli monitor

.\arduino-cli.exe monitor -p COM5 -c baudrate=115200

Gõ lệnh rồi nhấn Enter. Chữ đang gõ không hiện, nhưng sau Enter firmware in lại > lệnh. Thoát bằng Ctrl+C.

05.1.3 · Cách 3 · Tera Term

Serial, COM5, Setup → Serial port 115200 / 8 bit / None / 1 stop / Flow control none. Setup → Terminal: Receive = CR+LF, Transmit = CR.

Một cổng COM chỉ một chương trình dùng được tại một thời điểm. Trước khi nạp lại code (avrdude / arduino-cli upload) phải đóng PuTTY / monitor, nạp xong mở lại.

Khi mở cổng, UNO tự reset và in:

=== OJT CAN test node (Arduino UNO, protocol v1) ===
MCP2515 ready: 500000 bit/s, crystal 8000000 Hz, NORMAL mode
commands: play pause stop next prev | index <n> | ff [ms] | rew [ms] | status
          info | regs | selftest | spitest | raw <hex, 0..16 digits> | trace on|off | help
button D4: next demo step (PLAY, PAUSE, NEXT, PREV, FF, REW, INDEX 0, STOP, STATUS)

Kiểm tra dòng 2: crystal 8000000 Hz hay 16000000 Hz phải khớp với crystal module. Nếu là MCP2515 init FAILED (code 2) thì UNO không nói chuyện được với module: xem phần 10. Không thấy banner: nhấn nút RESET trên UNO.

05.2 · Kiểm tra node một mình (spitest, selftest)

Giữ J1, chưa nối CAN_H/CAN_L, nối đủ 7 dây UNO ↔ module (cả VCC 5V và GND). Chạy:

> spitest
SPITEST 1000 x 8 write/read + 2000 CANSTAT reads (1 MHz) ...
SPITEST PASS: 8000 write/read ok, CANSTAT stable (00) -> SPI wiring is good
> selftest
SELFTEST MCP2515 loopback ...
     (1) SPI ok, CONFIG mode
SELFTEST PASS: frame looped back, INT pin seen
     (4) back to NORMAL mode
     (5) transceiver OK: frame reached the bus, no ACK (normal if the bus is not connected)

Rút dây CAN_H rồi gõ play:

ERR  no ACK on CAN bus: frame aborted (Pi down? CAN_H/L swapped? termination? bitrate?)
     frame was sent, nobody acknowledged it  (TEC 0 -> 8, TXB0CTRL=18)
ERR  Pi offline: no STATUS for 1500 ms

Số ms, seq, số bài và thời lượng chỉ là ví dụ. Mẹo: mở song song SSH vào Pi chạy journalctl -u can-service -f để biết lỗi nằm ở phía UNO hay phía Pi.

06.5 · Dòng trace (cho người muốn hiểu bên trong)

Lệnh trace on (app tự gửi) làm firmware in thêm một dòng máy-đọc-được cho mỗi frame. Bạn cũng xem được các dòng này trong PuTTY:

#F,4022504,T,100,8,0101000000000000     frame: micros(), T=gửi / R=nhận, ID hex, DLC, data hex
#F,4030284,R,102,8,0101000000000000
#E,5120000,NOACK,128,24                 sự kiện: NOACK NOTSENT ARBLOST LOST TIMEOUT OFFLINE

Thời gian là micros() của Arduino lúc đọc frame từ MCP2515, sai số khoảng 1–4 ms do vòng lặp và việc in Serial. Như vậy đủ để xem chu kỳ 500/1000 ms và latency lệnh, nhưng không chính xác tới µs như phần cứng Vector.

08Test chạy dài (soak test)

Mục tiêu: hệ thống chạy liên tục 2 h (tối thiểu) đến 24 h, vừa phát/tua/chuyển bài vừa đo CPU và RAM (RSS) của từng process, để xem có crash hay rò rỉ bộ nhớ không.

Chuẩn bị: image minimal dùng ps của busybox, không có -o %cpu,rss. Thêm vào conf/local.conf khi build image test (không đưa vào bbappend production):

IMAGE_INSTALL:append = " procps sysstat"     # ps đầy đủ, pidstat

Script đo (copy vào Pi, ví dụ /usr/bin/monitor_resources.sh). PID lấy từ systemd (MainPID), vì các wrapper .sh đều exec binary; riêng GUI chạy dưới xinit nên lấy bằng pidof:

#!/bin/sh
# monitor_resources.sh [csv]: every 5 s log CPU %, RSS, VSZ and systemd restarts
OUT="${1:-/tmp/robustness_metrics.csv}"
echo "timestamp,service,pid,cpu_pct,rss_kb,vsz_kb,restarts" > "$OUT"
while true; do
    TS=$(date +"%Y-%m-%d %H:%M:%S")
    for SVC in media-manager video-player ojt-gui can-service; do
        if [ "$SVC" = ojt-gui ]; then PID=$(pidof ojt-gui)
        else PID=$(systemctl show -p MainPID --value "$SVC"); fi
        R=$(systemctl show -p NRestarts --value "$SVC")
        if [ -n "$PID" ] && [ "$PID" != 0 ]; then
            set -- $(ps -p "$PID" -o %cpu=,rss=,vsz=)
            echo "$TS,$SVC,$PID,$1,$2,$3,$R" >> "$OUT"
        else
            echo "$TS,$SVC,NOT_RUNNING,0,0,0,$R" >> "$OUT"
        fi
    done
    sleep 5
done

%cpu của ps là trung bình từ lúc process chạy. Muốn CPU theo từng khoảng 5 s thì chạy thêm pidstat -p <PID> 5.

Script tạo tải (dùng lệnh D-Bus; thêm dòng can-test.sh … nếu muốn tải cả đường CAN, khi Arduino đã nối bus):
