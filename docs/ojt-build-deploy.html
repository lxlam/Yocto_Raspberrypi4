Từ máy build Linux tới Pi chạy được: lấy layer, cấu hình, build image, ghi thẻ SD, boot, cập nhật qua SSH. Thêm: nạp firmware cho Arduino UNO bằng dòng lệnh và cài app OJT CAN Monitor trên PC.

01Máy build và layer Yocto

Đi từ máy build tới lúc giao diện hiện trên màn hình. Bước nào lỗi thì dừng ở bước đó, xem log trước khi đi tiếp.

01.1 · Máy build

Linux (Ubuntu 22.04 hoặc 24.04), ổ trống khoảng 100 GB, RAM từ 16 GB. Cài các gói host theo mục "Build Host Packages" trong Yocto Quick Start (bản Scarthgap). Nếu copy repo từ Windows sang, các file .sh phải giữ xuống dòng kiểu LF.

01.2 · Lấy layer và tạo thư mục build

Repo không chứa Poky và các layer upstream. Script scripts/setup-layers.sh clone chúng (nhánh scarthgap) vào rasp/poky/, tạo rasp/poky/build, add 4 layer và thêm cấu hình OJT vào cuối conf/local.conf. Chạy lại lần nữa là cập nhật layer, không thêm trùng.

cd Yocto_Raspberrypi4-main
bash scripts/setup-layers.sh
# kết quả:
#   rasp/poky/                  poky
#   rasp/poky/meta-raspberrypi  rasp/poky/meta-openembedded  rasp/poky/meta-qt5
#   rasp/poky/build/conf/       bblayers.conf + local.conf (đã có phần "OJT settings")

Làm tay (thay cho script):

cd rasp
git clone -b scarthgap https://git.yoctoproject.org/poky
cd poky
git clone -b scarthgap https://github.com/agherzan/meta-raspberrypi
git clone -b scarthgap https://github.com/openembedded/meta-openembedded
git clone -b scarthgap https://github.com/meta-qt5/meta-qt5
source oe-init-build-env build
bitbake-layers add-layer ../meta-raspberrypi
bitbake-layers add-layer ../meta-openembedded/meta-oe     # meta-qt5 cần layer này
bitbake-layers add-layer ../meta-qt5
bitbake-layers add-layer ../../custom-source/meta-ojt
bitbake-layers show-layers                                 # phải thấy đủ các layer trên

02Cấu hình local.conf

Script ở 01.2 đã thêm phần này. Làm tay thì thêm vào cuối rasp/poky/build/conf/local.conf:

MACHINE = "raspberrypi4-64"
INIT_MANAGER = "systemd"
DISTRO_FEATURES:append = " x11 opengl"
PACKAGECONFIG:append:pn-qtbase = " fontconfig"    # thiếu thì tên file tiếng Việt thành ô vuông

# Các service (media-manager, video-player, ojt-gui, can-service, can-service-test) và kernel-modules
# đã được thêm trong meta-ojt/recipes-core/images/core-image-minimal.bbappend, không cần thêm ở đây.
# SPI + MCP2515 (CAN) bật trong meta-ojt/recipes-bsp/bootsfile/rpi-config_%.bbappend.

# Màn Raspberry Pi 7" Touch Display (800×480, DSI). Bỏ dòng này nếu dùng HDMI
RPI_EXTRA_CONFIG = "dtoverlay=vc4-kms-dsi-7inch"

# Tiện cho test: SSH vào được, root không cần mật khẩu (chỉ dùng khi phát triển)
EXTRA_IMAGE_FEATURES += "ssh-server-dropbear debug-tweaks"

# Tuỳ chọn
IMAGE_INSTALL:append = " video-player-testdata"   # video mẫu trong /usr/share/video-player/testdata
LICENSE_FLAGS_ACCEPTED += "commercial"            # cần nếu bật gstreamer1.0-libav (AAC, H.265…)

Định dạng image: meta-ojt/recipes-core/images/core-image-minimal.bbappend đặt IMAGE_FSTYPES = "wic". Biến trong recipe/bbappend thắng giá trị trong local.conf, nên kết quả luôn là file .rootfs.wic (không nén). Muốn có .wic.bz2 + .wic.bmap để dùng bmaptool thì sửa dòng đó trong bbappend thành IMAGE_FSTYPES = "wic.bz2 wic.bmap".

Những gì layer meta-ojt tự làm, không cần thêm vào local.conf:

FileLàm gì
recipes-core/images/core-image-minimal.bbappendThêm network-config, media-manager, video-player, ojt-gui, can-service, can-service-test, kernel-modules vào image
recipes-bsp/bootsfile/rpi-config_%.bbappendENABLE_UART, ENABLE_SPI_BUS, ENABLE_CAN, CAN_OSCILLATOR, CAN0_INTERRUPT_PIN → config.txt
recipes-core/network-configeth0 IP tĩnh 192.168.2.20/24 (systemd-networkd)
recipes-connectivity/can-service/files/80-can0.networkBật can0 500 kbit/s, sample point 75 %, tự restart sau bus-off 100 ms

Recipe ojt-gui tự kéo theo packagegroup-core-x11-xserver (X server và driver đúng cho Pi), xinit, qtbase-plugins (platform xcb) và font ttf-dejavu-sans.

03.1 · Kiểm tra phần CAN trước khi ghi thẻ

bitbake -e rpi-config | grep -E '^(ENABLE_SPI_BUS|ENABLE_CAN|CAN_OSCILLATOR|CAN0_INTERRUPT_PIN)='
grep -E 'spi|mcp2515' tmp/deploy/images/raspberrypi4-64/bootfiles/config.txt
#   dtparam=spi=on
#   dtoverlay=mcp2515-can0,oscillator=8000000,interrupt=25
oe-pkgdata-util list-pkg-files can-service      # can-service, .service, 80-can0.network

Nếu crystal trên module phía Pi là 16 MHz: sửa CAN_OSCILLATOR = "16000000" trong rpi-config_%.bbappend. Crystal module phía UNO cấu hình riêng trong firmware (Phần cứng 05).

04Ghi image ra thẻ SD

File image: rasp/poky/build/tmp/deploy/images/raspberrypi4-64/core-image-minimal-raspberrypi4-64.rootfs.wic.

cd tmp/deploy/images/raspberrypi4-64/
lsblk                                                  # tìm thẻ SD, ví dụ /dev/sdb. Kiểm tra kỹ: ghi nhầm ổ là mất dữ liệu
sudo dd if=core-image-minimal-raspberrypi4-64.rootfs.wic of=/dev/sdX bs=4M status=progress conv=fsync

Trên Windows: Raspberry Pi Imager ("Use custom") hoặc balenaEtcher với file .wic. Nếu đã đổi sang wic.bz2 wic.bmap (02): sudo bmaptool copy …rootfs.wic.bz2 /dev/sdX.

05Boot, kiểm tra và vận hành

Lắp phần cứng theo Kết nối phần cứng (màn hình, module CAN, mạng), cắm thẻ SD, bật nguồn.

Bật nguồn. Khoảng 20–40 giây sau, màn hình hiện giao diện với dòng No playlist. Nối cáp mạng, đặt PC cùng dải (ví dụ 192.168.2.10/24) rồi kiểm tra qua SSH (ssh root@192.168.2.20):

systemctl status media-manager video-player ojt-gui can-service   # tất cả: active (running)
dmesg | grep mcp251x                                   # MCP2515 successfully initialized
ip -details link show can0                             # bitrate 500000, ERROR-ACTIVE
journalctl -u video-player | grep "Video sink"         # xvimagesink hoặc glimagesink
grep -E "vfat|exfat|ntfs" /proc/filesystems            # filesystem USB được hỗ trợ
dmesg | grep -iE "dsi|tc358762|ft5|panel"             # màn DSI đã được nhận chưa
media-manager-test.sh sim-add /usr/share/video-player/testdata   # test khi chưa có USB

Sau đó làm theo Kiểm thử: checklist USB/GUI và test CAN với Arduino.

06Cập nhật nhanh một chương trình qua SSH

Binary phải được build cho Pi (aarch64) bằng bitbake. Binary build bằng CMake trên PC (x86) không chạy được trên Pi.

# trên máy build: chỉ build lại recipe vừa sửa
bitbake video-player                 # hoặc can-service, media-manager, ojt-gui
BIN=tmp/work/cortexa72-poky-linux/video-player/1.0/image/usr/bin/video-player
PI=192.168.2.20                      # IP tĩnh của Pi (network-config)

scp $BIN root@$PI:/tmp/
ssh root@$PI 'systemctl stop video-player && mv /tmp/video-player /usr/bin/ && chmod +x /usr/bin/video-player && systemctl start video-player'

Đổi file cấu hình (config.txt, 80-can0.network, file .service) thì nên ghi lại thẻ, hoặc copy đúng file đó rồi systemctl daemon-reload / reboot.

08Nạp firmware Arduino UNO (CLI)

Không cần Arduino IDE: nạp bằng dòng lệnh. Source: arduino/ojt-can-node/. Cách nối UNO: Phần cứng 05–06.

Có hai cách. Cách A nhanh nhất: chỉ cần tải một file zip avrdude, vì file .hex đã build sẵn trong repo. Cách B dùng arduino-cli để build lại từ source, dùng khi bạn sửa code (đổi chân, đổi bitrate…). Mọi lệnh dưới đây gõ trong PowerShell hoặc Command Prompt (cmd).

08.1 · Tìm số cổng COM

Cắm cáp USB của UNO rồi chạy trong PowerShell:

Get-PnpDevice -Class Ports -PresentOnly | Select-Object FriendlyName

FriendlyName
------------
Arduino Uno (COM5)                   <- board chính hãng
USB-SERIAL CH340 (COM5)              <- board clone

Rút cáp ra rồi chạy lại: dòng nào biến mất chính là cổng của UNO. Dưới đây ví dụ dùng COM5 (máy của bạn đang là COM28), bạn thay bằng số của mình. (cmd thì gõ mode, sẽ liệt kê các COMx đang có.)

08.2 · Cách A · avrdude + file .hex có sẵn (khuyên dùng)

  1. Tải avrdude bản Windows từ trang GitHub avrdudes/avrdude → Releases, file avrdude-vX.Y-windows-x64.zip. Giải nén vào ví dụ C:\tools\avrdude\. Trong đó có avrdude.exe và avrdude.conf, không cần cài đặt.
  2. Xác định crystal trên module MCP2515 của UNO (chữ trên crystal: 8.000 hay 16.000) để chọn đúng file trong arduino\ojt-can-node\prebuilt\:
    Crystal moduleFile
    8 MHz (phổ biến)ojt-can-node-8mhz.hex
    16 MHzojt-can-node-16mhz.hex
  3. Đóng mọi chương trình đang mở COM5 (PuTTY, Tera Term…). Mở PowerShell trong thư mục repo rồi nạp: 
    cd D:\01_STUDY\FastTrack\Yocto_Raspberrypi4-main\Yocto_Raspberrypi4-main\arduino\ojt-can-node\prebuilt
C:\tools\avrdude\avrdude.exe -c arduino -p m328p -P COM5 -b 115200 -D -U flash:w:ojt-can-node-8mhz.hex:i

    Giải thích: -c arduino = nạp qua bootloader của UNO bằng cổng COM, -p m328p = chip ATmega328P, -b 115200 = tốc độ bootloader UNO, -D = không xoá chip trước (giống Arduino IDE), -U flash:w:file:i = ghi file Intel-hex vào flash.

  4. Kết quả đúng (số byte có thể khác chút tuỳ bản avrdude): 
    avrdude: AVR device initialized and ready to accept instructions
avrdude: device signature = 0x1e950f (probably m328p)
...
avrdude: writing 18426 bytes flash ...
...
avrdude: 18426 bytes of flash verified
...
avrdude done.  Thank you.

    Hai dòng quan trọng: device signature = 0x1e950f (đúng chip UNO) và … bytes of flash verified. Cách in chi tiết khác nhau một chút giữa các bản avrdude.

Cho gọn, trong thư mục prebuilt\ có sẵn flash.bat: copy avrdude.exe + avrdude.conf vào cùng thư mục đó (hoặc thêm thư mục avrdude vào PATH) rồi chạy:

flash.bat COM5          rem crystal 8 MHz
flash.bat COM5 16       rem crystal 16 MHz
flash.bat COM5 8 57600  rem UNO clone đời cũ (bootloader 57600)

File .hex được build từ source tại thời điểm tạo tài liệu này. Nếu bạn sửa code trong arduino/ojt-can-node/, file .hex không tự cập nhật: dùng cách B để build lại.

08.3 · Cách B · arduino-cli (build từ source)

Cần Internet tới downloads.arduino.cc ở lần chạy đầu (tải trình biên dịch AVR khoảng 150 MB). Nếu mạng công ty chặn trang này thì dùng cách A.

  1. Tải arduino-cli bản Windows 64-bit (GitHub arduino/arduino-cli → Releases, file arduino-cli_X.Y.Z_Windows_64bit.zip). Giải nén arduino-cli.exe vào ví dụ C:\tools\arduino-cli\.
  2. Cài bộ biên dịch cho UNO (chỉ làm một lần): 
    cd C:\tools\arduino-cli
.\arduino-cli.exe core update-index
.\arduino-cli.exe core install arduino:avr
  3. Kiểm tra board đã được nhận: 
    .\arduino-cli.exe board list

Port  Protocol Type              Board Name  FQBN            Core
COM5  serial   Serial Port (USB) Arduino Uno arduino:avr:uno arduino:avr

    Bản clone CH340 có thể không hiện Board Name: không sao, vẫn dùng -b arduino:avr:uno như bên dưới.

  4. Nếu crystal module là 16 MHz: mở arduino\ojt-can-node\app_can.h bằng Notepad, sửa thành #define APP_MCP2515_OSC_HZ 16000000UL.
  5. Build (đường dẫn là thư mục ojt-can-node, không phải file .ino): 
    $SK = "D:\01_STUDY\FastTrack\Yocto_Raspberrypi4-main\Yocto_Raspberrypi4-main\arduino\ojt-can-node"
.\arduino-cli.exe compile -b arduino:avr:uno $SK

Sketch uses 18426 bytes (57%) of program storage space. Maximum is 32256 bytes.
Global variables use 953 bytes (46%) of dynamic memory, leaving 1095 bytes for local variables.

    Số byte có thể lệch chút tuỳ bản arduino:avr.

  6. Nạp (đóng PuTTY trước): 
    .\arduino-cli.exe upload -b arduino:avr:uno -p COM5 $SK

    Không có dòng lỗi màu đỏ là xong. Muốn build và nạp trong một lệnh: .\arduino-cli.exe compile -b arduino:avr:uno -p COM5 -u $SK. Clone đời cũ nạp lỗi not in sync thì dùng -b arduino:avr:nano:cpu=atmega328old (cùng chip, bootloader 57600).

09Cài và chạy OJT CAN Monitor (PC)

App PC kiểu CANoe trong tools/can-monitor/. Cách dùng các tab: Kiểm thử 06.

09.1 · Cài đặt (Windows, một lần)

  1. Cài Python 3.8+ từ python.org, tick Add python.exe to PATH. Tkinter (thư viện cửa sổ) có sẵn trong bản cài này.
  2. Mở cmd trong thư mục tools\can-monitor: 
    py -m pip install -r requirements.txt
    (cài pyserial và matplotlib)
  3. Nạp lại firmware Arduino để có lệnh trace: 
    cd ..\..\arduino\ojt-can-node
arduino-cli compile -b arduino:avr:uno -p COM28 -u .

09.2 · Chạy

  1. Đóng arduino-cli monitor / PuTTY (một cổng COM chỉ một chương trình mở được).
  2. Double-click run.bat, hoặc gõ py can_monitor.py.
  3. Chọn cổng COM28 → Connect. UNO tự reset. Khi đèn cạnh nút chuyển xanh và hiện trace on là app đã nhận trace. Đèn Pi xanh = đang nhận STATUS từ Pi.
  4. Không có phần cứng: chọn DEMO (simulated Pi) để làm quen giao diện.
